# 19 Known Limitations

A frank list, written 2026-11-19 and refreshed 2026-11-20 after the two new features (Crisis Follow-Through Loop, docs/24, and Lifeline Offline, docs/25 and 26) were built. Resolved items are marked, not deleted, so the numbering that other documents use stays valid. New items L38 to L59 are at the end of section 2 (L49 and L50 are closed or fixed, see their rows). Anything claimed elsewhere in the docs should be read together with this page. MindSahaay is a student project. It is educational and is **not a medical device**; it does not diagnose or treat.

## 1. Evidence limits

| # | Limitation | Consequence |
|---|---|---|
| L1 | **The crisis-detection dataset is synthetic.** 600 messages written for the project; none come from real students. | Results may not transfer to real text. |
| L2 | **Single annotator.** The author wrote and labelled every item. No inter-annotator agreement. | Label noise and bias are unmeasured. |
| L3 | **No clinician review.** Neither the label rubric, nor the lexicon, nor the AI prompt, nor the crisis wording, nor the safety plan content has been reviewed by a qualified clinician or counsellor. | No clinical claim may be made. The clinical safety case (08) is a draft by a non-clinician. |
| L4 | **Low effective diversity.** About 210 distinct core sentences expanded to 600 with openers and closers. | Confidence intervals computed on 600 items would be too narrow. |
| L5 | **Dev scores are overfit.** Keyword v2 reaches 0.975 on dev because the rules were designed on dev items. | Never quote dev scores. The heldout figure (0.70 recall) is the only usable number, and it is still optimistic. |
| L6 | **Heldout recall (0.70) is below the 0.95 target.** The keyword layer alone misses many high and imminent messages, especially euphemisms, attempts in progress and Hindi paraphrases. | The LLM layer is required, and even then the target is unproven. |
| L7 | **LLM-only and hybrid results do not exist.** They are PENDING and need a human with an API key. | The hybrid design is untested. The "fail-safe OR" claim in the SRS is a design intent, not a measured result. |
| L8 | **No real user study.** No survey, interviews or usability test (SUS) has been carried out. No ethics approval is recorded. | Claims about usefulness, usability and acceptance are unsupported. |
| L9 | **No measured performance.** No Lighthouse, load test, TTFT or latency figures for the full system. The only number is the first-route bundle size, about 190.9 KB gzipped (inside the 200 KB budget, down from 246.9 KB after lazy-loading the Supabase SDK and the Hindi locale). | NFR-PERF items are unverified. Bundle size is not a performance score. |

## 4. What this project can honestly claim

- A working front end with 910 passing Vitest tests (1 skipped; 81 files; includes the edge-function tests) and 102 passing Playwright tests (Chromium only, including 57 axe combinations with zero serious or critical violations), 0 TypeScript errors and 0 ESLint errors on `src`. Line coverage is 91.99% over the configured scope.
- A privacy-oriented database and API that run on a local Supabase stack: 28 tables with RLS, 184 pgTAP tests passing in 15 files (migrations 0001 to 0009), 24 passing real-backend Playwright tests before the newest specs (see `e2e/real`), the edge function verified on the real edge runtime with real JWTs, and a real-session browser check of the main routes. Not run on a hosted project; the Claude and Daily.co routes are unverified.
- Sensitive local data (CBT records, safety card anchors, trusted contact) stored only as AES-GCM ciphertext, browser-verified.
- A deterministic crisis lexicon with an honestly measured heldout recall of 0.70 and no false alarms on 45 hard negatives, on synthetic data.
- A transparent evaluation procedure, with the LLM and hybrid runs ready to be executed.
- A recorded, in-app follow-up loop for high and crisis risk events, and an encrypted offline outbox, both exercised in real browsers against a local Supabase (by hand and by the eal Playwright suite). Neither is a staffed or 24/7 service.

Fixed on 2026-11-27 and therefore not listed as limitations: invented dashboard values (78/100 wellbeing, 24/100 stress, a 4-day streak, sleep and step counts, a fake chart), "Saved locally" shown after a failed mood save, an invented trusted contact and safety-plan people, invented consent defaults and screening history, sample stories presented as real, silent data loss in the CBT activity and worry tools with a locked vault, and swallowed write errors in onboarding, assessment and reporting (docs/31, docs/32).

It cannot claim clinical validity, regulatory compliance, measured usability, or measured production performance.
