# Abstract

> Draft 2, numbers as measured on 2026-11-20. The abstract must be re-checked last against the final numbers. Items in square brackets are placeholders that only the student can fill.

MindSahaay is a privacy-first, educational web platform for wellbeing support among Indian university students. It combines mood tracking, educational self-screening (PHQ-4, PHQ-9 and GAD-7), an end-to-end encrypted journal, a Claude-based AI companion that replies in English, Hindi and Hinglish, counsellor appointment booking, and moderated peer circles. The platform does not diagnose, treat or monitor, and it is not a medical device. It never shares individual data with a university.

The report describes the design and construction of a React 19, Vite, Tailwind CSS v4 and TypeScript front end with a Supabase back end (Postgres with row level security, and a Hono edge function that proxies the Claude API). Three engineering decisions shape the system. First, a deterministic safety layer is placed in front of everything else: a PHQ-9 item 9 response above zero always triggers the crisis protocol regardless of total score, and a multilingual keyword lexicon screens every free-text input and shows the helplines Tele-MANAS 14416, KIRAN 1800-599-0019 and emergency 112 without calling a model. Second, journal entries are encrypted in the browser with AES-256-GCM under a key derived from the student's passphrase by PBKDF2-SHA-256 with 600,000 iterations, so the server holds only ciphertext. Third, institutional reporting is limited to aggregate database views that suppress any group smaller than ten records. Two further features were chosen late, by a structured AI-panel selection described in the report and not validated with users: a recorded follow-up loop for high-risk events (five ordered steps, in-app overdue notifications, student check-backs) and an offline layer (a service worker and an encrypted on-device outbox) that keeps the helplines available without a network. Neither is a staffed or 24/7 service, and nobody is alerted while a device is offline.

Verification so far is partial and is reported as such. As of 20 November 2026 the Vitest suite has 71 files passed (1 skipped, a live smoke test that needs tokens) and 818 tests passed (1 skipped), with the network mocked; line coverage is 90.61 percent, statements 88.62, branches 80.56 and functions 86.44, with thresholds enforced. The default Playwright run passed 102 tests in Chromium and the PWA project (including 57 accessibility combinations with zero serious or critical violations), and a separate real-backend project passed 5 tests against a local Supabase stack. TypeScript has 0 errors and ESLint 0 errors and 0 warnings. On a local Supabase stack, 28 tables with row level security and 146 pgTAP tests in 14 files pass (migrations 0001 to 0008), and the edge function was verified on the real edge runtime with real JWTs. Of the requirements, 3 of 72 are Implemented, 60 Partial and 9 Not started. The crisis lexicon was evaluated on a synthetic 600-message dataset in three languages. On the held-out half, recall for high and imminent risk messages was 0.30 for the first keyword version and 0.70 for the second, against a design target of 0.95. The 0.975 score of the second version on development data is overfit and is not treated as a result. Evaluation of the LLM-only and hybrid detectors is pending because it needs an API key. Running the system found real defects, each fixed with a regression test: students could resolve their own crisis events, six SQL errors appeared only on a real Postgres, an offline crisis event could be lost, and an independent review found a Critical defect (an event reopened by the student was not escalated again), fixed in migration 0007. The database has not been run on a hosted project, the Claude and video routes are unverified, Lighthouse and OWASP ZAP were not run, the browser tests covered Chromium only and not a phone, nobody is alerted while a device is offline, and nothing is deployed.

The principal limitations are synthetic evaluation data written and labelled by one person, no clinician review, no hosted deployment, and no user study.
