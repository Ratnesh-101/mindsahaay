## Setup (do this before the audience arrives)

- Fictional persona (Aarav). Synthetic data only. **The way to demo is the Demo data button**: sign in to a real local account, open Settings and press Load demo data (about 30 days of sample check-ins and 3 sample screenings, all labelled Demo). Press Clear demo data afterwards, and before each rehearsal. A fresh account shows empty states with real zeros on purpose, so load the demo data before the audience arrives. Demo rows are hidden from the counsellor window and never raise a crisis alert. Night mode ready, phone on silent, helpline links shown but **never dialled**. Have a backup screen recording in case of failure.
- **The login page also has an offline preview button, now labelled "Offline preview (sample data, no account)".** It is only for looking at the interface when no backend is running; its flag lives in `sessionStorage`, so a new tab starts as the normal app. It cannot load or clear demo data. **Steps 6 and 7 need the real local backend, not the offline preview.** The preview has no session, no service worker and no outbox. Start the local Supabase stack (17-deployment-guide.md section 12), build and serve a non-demo production build (`pnpm build` then `pnpm preview`), and keep the mail catcher open for the magic link.
- **Two browser windows:** window A is the student (normal profile), window B is the counsellor (a private window or a second profile). The counsellor must hold a current care share with scope `risk_events` for the student (the seed data has such shares for the demo accounts; TODO confirm which pair and that one event has an `acknowledged` step with a check-back that is already due, or make the h24 prompt due with SQL before the demo).
- **Warm the offline path while online, at least 30 seconds before the demo:** sign in as the student, visit `/dashboard`, `/crisis` and `/chat` once (this installs the service worker), unlock the journal vault (the offline queue needs it), and make sure the crisis consent is given (this fills the consent cache). If any of these is skipped, step 6 will show the crisis card but will **not** queue an event, and you must say so.
- Prototype caveat: items marked (target) rely on features not yet built; skip or show slides.

## Contingency

- API failure: show the keyword fallback and the timeout message (this demonstrates FR-AI-09).
- Backend or second window not working: skip step 7 and show the recording or the state diagram in 24-crisis-followup.md. Do not describe the loop as live if it was not.
- Offline step shows no cached page: the service worker needs one earlier online visit and a non-demo production build. Fall back to the screenshot of the offline page and say so.
- Event was not queued while offline: the vault was locked or the consent cache was empty (limitations L39, L42). Say that this is a real limit, not a demo glitch.
- The reopen-does-not-re-escalate defect (G6-SEC-01) was fixed in migration 0007 and is covered by pgTAP files 12 and 13. Say "covered by database tests", not "verified in a browser".
- Realtime fails if the stack was started without migration 0008: the new event then shows only after a reload. Say so and reload; do not hide it.
- Optional, only if time allows and window A has a due offer: in step 7 the counsellor can use "Offer a session" (migration 0006) and the student can accept it on the Dashboard. This adds about 40 seconds, so drop step 3 first. Say it books a session in the app and nothing more. Not checked in a browser by the documentation worker.
- If no care share exists, the student card says "Alert recorded. It was not shared with a counsellor." with the helplines first (the earlier wording was defect G6-SEC-05, now fixed). Do not describe that case as "the counsellor has been told".
- Time over: drop step 2, then step 3, then step 8.
- Likely questions: why not diagnose, what if the model misses a crisis, who can read my chat, how is Hinglish tested, DPDP cross-border handling, who is told when I am offline, who reads the alerts at night, can a student hide their own alert. Answers are in 07, 08, 11, 24, 25 and slides/qa-prep.md.
